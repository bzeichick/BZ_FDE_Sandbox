## Week 3: non-text content (Session 6's four questions)

1. **Visual, or text as pixels?** Text as pixels. 375 attachment PDFs have no text layer (scanned bills of lading, POs and appointment confirmations, some with handwritten corrections), plus appointment-portal screenshots in email threads. Nobody asks what a BOL looks like; they ask for the PO, pallets or appointment on it.
2. **Does the number live only in the pixels; what finds it, reads it, checks it?** For those 375, yes (e.g. a handwritten pallet count over the printed one). Strategy A: parse each scan to text once, index it with BM25 so identifiers match exactly, and have a vision model re-read the pixels only for the few matching scans when a field is in doubt. Every reading is checked against the shipment's TMS record (PO, pallets, weight, temperature) and the customer's reference format; a handwritten change keeps both values ("printed 8, handwritten 6") and goes to a person.
3. **Descriptions, or one parse per image; where does the batch run?** No descriptions exist, so one parse per scan: 375 documents is a one-off batch, then only new scans from the weekday mail pull. It runs on the broker's server with the LLM provider already approved, so no new vendor. Signature-logo images (most images by count) are skipped at extraction and never parsed. Not run yet: today the 375 are simply absent from the corpus.
4. **Video or audio: does the transcript answer it?** None today. Every order is confirmed by email; calls are used only for negotiation and aren't recorded. If calls were recorded, the transcript alone would answer most questions (rates and dates agreed are spoken, not shown).
